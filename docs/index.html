01

Configuracion inicial

Identidad (obligatorio)

  • git --version

    Comprueba que Git esté instalado y su versión.

  • git config --global user.name "Bran0017"

    Nombre que aparecerá en cada commit.

  • git config --global user.email "tu@mail.com"

    Debe coincidir con el correo de tu cuenta de GitHub.

  • git config --global init.defaultBranch main

    Que los repos nuevos usen "main" en vez de "master".

  • git config --global core.editor "code --wait"

    Usar VS Code como editor de mensajes de commit.

  • git config --global pull.rebase false

    Define el comportamiento por defecto de git pull.

Ver y editar la configuración

  • git config --list

    Lista toda la configuración activa.

  • git config --list --show-origin

    Además indica en qué archivo está definido cada valor.

  • git config user.name

    Consulta un valor concreto.

  • git config --global --edit

    Abre ~/.gitconfig en tu editor.

  • git config --global color.ui auto

    Activa colores en la salida de la terminal.

  • git config --global --unset alias.st

    Elimina una clave de la configuración.

Windows / Linux / saltos de línea

  • git config --global core.autocrlf true

    En Windows: convierte finales de línea al hacer checkout.

  • git config --global core.autocrlf input

    En Linux, Mac o WSL: guarda siempre en formato LF.

  • git config --global core.longpaths true

    Windows: evita el error de rutas demasiado largas.

  • git config --global credential.helper store

    Guarda usuario y token para no escribirlos cada vez.

  • git config --global credential.helper manager

    Windows: usa el gestor de credenciales del sistema.

Archivo .gitignore

  • echo "node_modules/" >> .gitignore

    Agrega una regla para ignorar carpetas o archivos.

  • echo ".env" >> .gitignore

    Nunca subas claves ni variables de entorno al repositorio.

  • git check-ignore -v archivo.txt

    Dice qué regla del .gitignore está ignorando un archivo.

  • git rm -r --cached .

    Limpia el índice para reaplicar un .gitignore ya existente.

  • git status --ignored

    Muestra también los archivos que están siendo ignorados.

Ayuda

  • git help commit

    Manual completo de un comando.

  • git commit -h

    Resumen rápido de opciones.

Tip

Usa --global para configurar todo tu usuario y omítelo para configurar solo el repositorio actual. Lo local siempre pisa a lo global.

Antes de empezar

Sin user.name y user.email configurados, Git se niega a crear commits. Es lo primero que debes hacer en una máquina nueva.

02

Conexión por SSH

Paso 1 · Generar la llave

  • ssh-keygen -t ed25519 -C "tu@mail.com"

    Crea el par de llaves. Cuando pregunte la ruta presiona ENTER: no escribas nada.

  • ssh-keygen -t rsa -b 4096 -C "tu@mail.com"

    Alternativa si el sistema es antiguo y no soporta ed25519.

  • ls -la ~/.ssh

    Debes ver id_ed25519 (privada) e id_ed25519.pub (pública).

  • ssh-keygen -l -f ~/.ssh/id_ed25519.pub

    Muestra la huella digital de la llave.

Paso 2 · Cargar el agente

  • eval "$(ssh-agent -s)"

    Inicia el agente SSH en la sesión actual.

  • ssh-add ~/.ssh/id_ed25519

    Agrega tu llave privada al agente.

  • ssh-add -l

    Lista las llaves cargadas en el agente.

  • ssh-add -D

    Descarga todas las llaves del agente.

Paso 3 · Copiar la llave pública

  • cat ~/.ssh/id_ed25519.pub

    Copia la salida completa y pégala en GitHub › Settings › SSH keys.

  • clip < ~/.ssh/id_ed25519.pub

    Windows: copia directo al portapapeles.

  • pbcopy < ~/.ssh/id_ed25519.pub

    macOS: copia directo al portapapeles.

  • xclip -sel clip < ~/.ssh/id_ed25519.pub

    Linux: copia directo al portapapeles.

Paso 4 · Probar y usar

  • ssh -T git@github.com

    Respuesta esperada: "Hi usuario! You have successfully authenticated".

  • ssh -vT git@github.com

    Modo detallado: útil para ver por qué falla la autenticación.

  • git clone git@github.com:usuario/repo.git

    Clonar usando SSH en vez de HTTPS.

  • git remote set-url origin git@github.com:usuario/repo.git

    Cambia un repo existente de HTTPS a SSH.

  • git remote -v

    Verifica que la URL empiece por git@ y no por https://

Permisos y arreglos

  • chmod 700 ~/.ssh

    La carpeta debe ser privada o SSH la rechaza.

  • chmod 600 ~/.ssh/id_ed25519

    La llave privada solo la puede leer tu usuario.

  • chmod 644 ~/.ssh/id_ed25519.pub

    La llave pública sí puede ser legible.

  • mv "nombre-raro" id_ed25519

    Si guardaste la llave con otro nombre, renómbrala así.

  • rm ~/.ssh/id_ed25519*

    Borra el par de llaves para empezar de cero.

Error típico al generar la llave

Cuando aparece Enter file in which to save the key NO escribas un comando ni un nombre: presiona ENTER. Si escribes algo, la llave se guarda con ese nombre y Git nunca la encuentra.

SSH vs HTTPS

HTTPS pide usuario y token en cada operación. SSH autentica con la llave y no vuelve a preguntar nada. Para trabajo diario, SSH.

03

Crear y clonar repositorios

Iniciar un repositorio local

  • git init

    Convierte la carpeta actual en repositorio: crea la carpeta oculta .git.

  • git init nombre-proyecto

    Crea la carpeta y la inicializa de una sola vez.

  • git init --bare repo.git

    Repositorio sin archivos de trabajo, usado como servidor central.

  • git status

    Confirma que estás dentro de un repo y ve su estado.

  • git rev-parse --show-toplevel

    Muestra la raíz del repositorio en el que estás.

Clonar un repositorio existente

  • git clone https://github.com/user/repo.git

    Copia el repo remoto completo con todo su historial.

  • git clone git@github.com:user/repo.git

    Lo mismo pero vía SSH, sin pedir contraseña.

  • git clone URL carpeta-destino

    Clona dentro de una carpeta con el nombre que tú elijas.

  • git clone --depth 1 URL

    Clon superficial: solo el último commit. Mucho más rápido.

  • git clone -b develop URL

    Clona directamente una rama específica.

  • git clone --recurse-submodules URL

    Clona también los submódulos del proyecto.

Conectar con el remoto

  • git remote add origin URL

    Vincula tu repo local con el remoto llamado "origin".

  • git remote -v

    Muestra las URLs de fetch y de push configuradas.

  • git remote set-url origin URL

    Cambia la dirección del remoto.

  • git remote rename origin upstream

    Renombra un remoto.

  • git remote remove origin

    Elimina el vínculo con ese remoto.

  • git remote show origin

    Detalle completo: ramas, seguimiento y estado.

Primer push completo

  • git add .

    Prepara todos los archivos.

  • git commit -m "initial commit"

    Crea el primer commit.

  • git branch -M main

    Renombra la rama actual a main.

  • git push -u origin main

    Sube y deja main vinculada a origin/main.

fatal: not a git repository

Significa que en esa carpeta no existe .git ni en ninguna carpeta superior. Estás en la ruta equivocada, o nunca ejecutaste git init / git clone ahí.

04

Flujo diario

Preparar cambios (staging)

  • git status

    Qué cambió, qué está preparado y en qué rama estás.

  • git status -s

    Versión corta y compacta del estado.

  • git add archivo.txt

    Prepara un archivo concreto.

  • git add .

    Prepara todo desde la carpeta actual hacia abajo.

  • git add -A

    Prepara todo el repositorio, incluidos los borrados.

  • git add *.js

    Prepara por patrón: todos los archivos .js

  • git add -p

    Interactivo: elige trozo por trozo qué incluir.

  • git reset archivo.txt

    Saca un archivo del área de preparación.

Confirmar (commit)

  • git commit -m "mensaje claro"

    Guarda los cambios preparados en el historial.

  • git commit -am "mensaje"

    Agrega y confirma en un paso, solo archivos ya rastreados.

  • git commit --amend -m "nuevo msg"

    Corrige el último commit o su mensaje.

  • git commit --amend --no-edit

    Agrega cambios al último commit sin tocar el mensaje.

  • git commit --allow-empty -m "trigger"

    Commit vacío, útil para disparar un pipeline.

Ver diferencias

  • git diff

    Cambios que aún NO están preparados.

  • git diff --staged

    Cambios ya preparados, listos para el commit.

  • git diff main..develop

    Diferencias entre dos ramas.

  • git diff --stat

    Resumen: archivos tocados y líneas añadidas o borradas.

  • git diff HEAD~1 HEAD

    Qué cambió en el último commit.

Historial

  • git log

    Historial completo de commits.

  • git log --oneline --graph --all

    El mejor: árbol visual y compacto de todas las ramas.

  • git log -5

    Solo los últimos cinco commits.

  • git log -p archivo.txt

    Historial con los cambios concretos de un archivo.

  • git log --since="2 weeks ago"

    Filtra el historial por fecha.

  • git show HEAD

    Detalle completo del último commit.

  • git blame archivo.txt

    Quién escribió cada línea y en qué commit.

  • git shortlog -sn

    Ranking de commits por autor.

  • git reflog

    Todo lo que hiciste, incluso lo "perdido". Tu red de seguridad.

05

Sincronizar con el remoto

Subir cambios · push

  • git push

    Sube la rama actual a su remoto vinculado.

  • git push -u origin main

    Primera vez: sube y crea el vínculo de seguimiento.

  • git push origin nombre-rama

    Sube una rama concreta.

  • git push --all origin

    Sube todas las ramas locales.

  • git push origin --delete rama

    Borra una rama en el remoto.

  • git push --tags

    Sube todas las etiquetas.

  • git push --force-with-lease

    Forzar de forma segura: aborta si alguien más subió algo.

  • git push --dry-run

    Simulacro: muestra qué subiría sin subir nada.

Traer cambios · fetch

  • git fetch origin

    Descarga los cambios del remoto SIN tocar tu trabajo.

  • git fetch --all

    Descarga desde todos los remotos configurados.

  • git fetch --prune

    Además borra referencias a ramas que ya no existen.

  • git log main..origin/main

    Ve qué commits nuevos trajo el fetch antes de integrarlos.

  • git diff main origin/main

    Compara tu rama con la del remoto.

Traer e integrar · pull

  • git pull

    Equivale a git fetch + git merge de un solo golpe.

  • git pull origin main

    Trae e integra una rama concreta.

  • git pull --rebase

    Integra reescribiendo encima: historial lineal, sin commit de merge.

  • git pull --ff-only

    Solo avanza si no hay divergencia; si la hay, aborta.

Cuando el push es rechazado

  • git pull --rebase origin main

    La solución normal a "non-fast-forward": integra y reintenta el push.

  • git pull origin main --allow-unrelated-histories

    Cuando el repo remoto ya tenía un README y el local su propio commit inicial.

  • git push -f origin main

    Último recurso: sobrescribe el remoto. Puede borrar trabajo ajeno.

fetch vs pull

fetch = mirar sin comprometerse: descarga y tú decides qué hacer. pull = fetch + merge automático. Si no estás seguro usa fetch, revisa con git log y luego haz merge.

Rutina segura

Antes de empezar a trabajar: git pull. Antes de subir: git pull --rebase y después git push. Así casi nunca tendrás conflictos feos.

06

Ramas, merge y rebase

Gestionar ramas

  • git branch

    Lista las ramas locales; la actual lleva asterisco.

  • git branch -a

    Lista las ramas locales y las remotas.

  • git branch -v

    Muestra el último commit de cada rama.

  • git branch nueva-rama

    Crea una rama sin cambiarte a ella.

  • git switch -c nueva-rama

    Crea la rama y se cambia. Forma moderna recomendada.

  • git checkout -b nueva-rama

    Lo mismo con la sintaxis clásica.

  • git switch main

    Cambia a una rama que ya existe.

  • git switch -

    Vuelve a la rama anterior.

  • git branch -m nuevo-nombre

    Renombra la rama actual.

  • git branch -d rama

    Borra la rama si ya fue integrada.

  • git branch -D rama

    Borra a la fuerza aunque no esté integrada.

  • git branch --merged

    Lista las ramas ya integradas: las que puedes borrar.

Merge

  • git merge develop

    Integra develop dentro de la rama en la que estás parado.

  • git merge --no-ff develop

    Fuerza un commit de merge para conservar la historia de la rama.

  • git merge --squash develop

    Aplana todos los commits de la rama en uno solo.

  • git merge --abort

    Cancela el merge y deja todo como estaba.

Rebase

  • git rebase main

    Reaplica tus commits encima de main: historial lineal.

  • git rebase -i HEAD~3

    Interactivo: reordena, junta o reescribe los últimos tres commits.

  • git rebase --continue

    Continúa tras resolver un conflicto.

  • git rebase --skip

    Salta el commit conflictivo actual.

  • git rebase --abort

    Cancela el rebase por completo.

Conflictos

  • git status

    Lista los archivos en conflicto.

  • git add archivo-resuelto

    Marca el conflicto como resuelto tras editarlo.

  • git checkout --ours archivo

    Se queda con tu versión.

  • git checkout --theirs archivo

    Se queda con la versión que llega.

Regla de oro

Nunca hagas rebase de commits que ya subiste y otros descargaron: reescribe la historia y rompe el repositorio de tus compañeros.

07

Deshacer cambios

Descartar cambios locales

  • git restore archivo.txt

    Descarta los cambios no guardados de un archivo.

  • git restore .

    Descarta TODOS los cambios sin preparar. No hay vuelta atrás.

  • git restore --staged archivo

    Saca del área de preparación sin perder el cambio.

  • git restore --source HEAD~2 archivo

    Recupera la versión de un archivo de dos commits atrás.

  • git checkout -- archivo.txt

    Equivalente clásico de git restore.

  • git clean -n

    Simulacro: muestra qué archivos sin rastrear borraría.

  • git clean -fd

    Borra de verdad archivos y carpetas sin rastrear.

Reset · mueve el HEAD

  • git reset --soft HEAD~1

    Deshace el commit pero conserva todo preparado.

  • git reset --mixed HEAD~1

    Deshace commit y staging; conserva los archivos.

  • git reset --hard HEAD~1

    Borra el commit y los cambios. Destructivo.

  • git reset --hard origin/main

    Deja tu rama exactamente igual a la del remoto.

  • git reset HEAD~3 --soft

    Junta los últimos tres commits para rehacerlos en uno.

Revert · seguro para equipos

  • git revert HEAD

    Crea un commit nuevo que anula el último. No reescribe la historia.

  • git revert abc1234

    Anula un commit concreto por su hash.

  • git revert --no-commit HEAD~3..HEAD

    Anula un rango y lo deja todo preparado en un solo commit.

  • git revert -m 1 <hash-merge>

    Revierte un commit de merge.

Stash · guardar para después

  • git stash

    Guarda los cambios en curso y deja la carpeta limpia.

  • git stash push -m "wip login"

    Guarda con un nombre para identificarlo después.

  • git stash -u

    Guarda también los archivos sin rastrear.

  • git stash list

    Lista todo lo guardado.

  • git stash show -p stash@{0}

    Ve el contenido de un stash antes de aplicarlo.

  • git stash pop

    Recupera el último y lo elimina de la pila.

  • git stash apply stash@{1}

    Recupera uno concreto sin borrarlo de la pila.

  • git stash drop stash@{0}

    Elimina una entrada del stash.

  • git stash clear

    Vacía todo el stash.

¿Lo perdiste? git reflog

reflog guarda cada movimiento del HEAD. Busca el hash del punto al que quieres volver y ejecuta git reset --hard <hash>.

08

Tags, alias y atajos

Tags / versiones

  • git tag

    Lista las etiquetas del repositorio.

  • git tag v1.0.0

    Etiqueta ligera en el commit actual.

  • git tag -a v1.0.0 -m "Release 1.0"

    Etiqueta anotada con autor, fecha y mensaje.

  • git tag -a v1.0 abc1234

    Etiqueta un commit antiguo por su hash.

  • git show v1.0.0

    Detalle de la etiqueta y del commit al que apunta.

  • git push origin v1.0.0

    Sube una etiqueta concreta al remoto.

  • git push origin --tags

    Sube todas las etiquetas.

  • git tag -d v1.0.0

    Borra una etiqueta local.

  • git push origin --delete v1.0.0

    Borra la etiqueta también en el remoto.

Buscar en el historial

  • git grep "texto"

    Busca una cadena en todos los archivos rastreados.

  • git log --grep="login"

    Busca commits por su mensaje.

  • git log --author="Bran"

    Filtra los commits por autor.

  • git log -S "funcion()"

    Encuentra el commit donde apareció o desapareció un texto.

  • git bisect start

    Búsqueda binaria para hallar el commit que rompió algo.

Alias · escribe menos

  • git config --global alias.st status

    Ahora "git st" equivale a git status.

  • git config --global alias.co checkout

    "git co" equivale a git checkout.

  • git config --global alias.br branch

    "git br" equivale a git branch.

  • git config --global alias.cm "commit -m"

    "git cm" equivale a git commit -m.

  • git config --global alias.lg "log --oneline --graph --all"

    El alias estrella: "git lg" dibuja el árbol completo.

  • git config --global alias.last "log -1 HEAD"

    "git last" muestra el último commit.

  • git config --global alias.unstage "reset HEAD --"

    "git unstage archivo" lo saca del staging.

  • git config --global alias.amend "commit --amend --no-edit"

    "git amend" agrega al último commit sin abrir el editor.

Atajos de referencia

  • HEAD

    El commit en el que estás parado ahora mismo.

  • HEAD~1 / HEAD~3

    Uno o tres commits hacia atrás.

  • HEAD^

    El primer padre del commit actual.

  • origin/main

    La rama main tal y como está en el remoto.

  • git checkout -

    Vuelve a la rama anterior, igual que "cd -".

  • . / -A / -p

    Alcances de git add: carpeta actual, todo, interactivo.

09

Errores comunes

Comandos de rescate

  • git reflog

    Ve todo lo que hiciste; desde aquí se recupera casi cualquier cosa.

  • git reset --hard <hash>

    Vuelve exactamente a ese punto del historial.

  • git merge --abort

    Cancela un merge conflictivo.

  • git rebase --abort

    Cancela un rebase a medias.

  • git checkout <hash> -- archivo

    Recupera un solo archivo desde un commit antiguo.

Higiene del repositorio

  • git fsck

    Verifica la integridad de la base de datos de objetos.

  • git gc --prune=now

    Compacta y limpia objetos sueltos.

  • git count-objects -vH

    Cuánto pesa realmente tu repositorio.

  • git rm --cached archivo

    Deja de rastrear un archivo sin borrarlo del disco.

  • git mv viejo.txt nuevo.txt

    Renombra un archivo y registra el cambio en Git.

Diagnóstico rápido

  • git status

    Primer comando siempre: te dice dónde estás y qué pasa.

  • git remote -v

    Confirma a qué remoto apuntas realmente.

  • git branch -vv

    Muestra cada rama y la rama remota que sigue.

fatal: not a git repository

No hay carpeta .git en esa ruta ni en las superiores. Comprueba dónde estás y ejecuta git init o git clone.

rejected · non-fast-forward

El remoto tiene commits que tú no tienes. Solución: git pull --rebase y después git push.

refusing to merge unrelated histories

Dos historiales independientes. Usa git pull origin main --allow-unrelated-histories.

Permission denied (publickey)

SSH no encuentra o no acepta tu llave. Revisa ssh-add -l, los permisos con chmod 600 y que la llave pública esté cargada en GitHub.

src refspec main does not match any

Todavía no existe ningún commit. Haz git add . y git commit -m "init" antes del push.

detached HEAD

Estás parado en un commit suelto y no en una rama. Sal con git switch main, o guarda el trabajo con git switch -c rama-nueva.

Your local changes would be overwritten

Tienes cambios sin guardar que chocan con lo que llega. Haz git stash, luego git pull y después git stash pop.

Please tell me who you are

Falta configurar la identidad. Ejecuta git config --global user.name y user.email.
